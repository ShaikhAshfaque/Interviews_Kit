SENIOR ML ENGINEER: BASIC TO ADVANCED 200 IMPORTANT POINTS

==============================
SECTION 1: ML FUNDAMENTALS
==============================

1. Machine Learning (ML):
In ML, a machine learns patterns from data to make predictions or decisions.

2. AI vs ML vs Deep Learning:
AI is the broad field, ML is a subset of AI, and Deep Learning is a subset of ML that uses neural networks.

3. Supervised ML Learning:
Training a model on labeled data, such as house price prediction.

4. Unsupervised Learning:
Finding patterns and groups in unlabeled data, such as customer segmentation.

5. Reinforcement Learning:
An agent learns through actions, rewards and feedback from an environment.

6. Classification:
Predicting a discrete class, such as fraud or not fraud.

7. Regression:
Predicting a continuous numerical value, such as sales or house price.

8. Train, Validation, Test Split:
The model learns on the training set, the validation set is used for tuning, and the test set is used for final evaluation.

9. Overfitting:
The model learns the training data too closely and performs poorly on unseen data.

10. Underfitting:
The model fails to learn even the important patterns in the data.

11. Bias-Variance Tradeoff:
Bias is error from overly simple assumptions; variance is the model's sensitivity to changes in the training data.

12. Generalization:
The model performing well on unseen real-world data.

13. Features:
Input variables the model uses to predict, such as age, income and transaction amount.

14. Labels/Targets:
The output the model learns to predict.

15. Baseline Model:
A simple reference model against which the performance of advanced models is compared.

16. Parametric vs Non-parametric:
Parametric models use a fixed form with a fixed set of parameters; the effective complexity of non-parametric models can grow with the data.

17. Batch Learning:
Training a model on a collected dataset, generally as a scheduled process.

18. Online Learning:
Updating the model incrementally as new data arrives.

19. Transfer Learning:
Reusing the learned representations of a pretrained model for a new task.

20. Reproducibility:
Being able to reproduce results with the same code, data version, configuration and environment.

==============================
SECTION 2: STATISTICS & MATHEMATICS
==============================

21. Mean, Median, Mode:
Mean is the average, median is the middle value, and mode is the most frequent value.

22. Variance:
A squared-deviation-based measure of how spread out data points are from the mean.

23. Standard Deviation:
The square root of variance; it shows the spread of the data in the original units.

24. Probability:
The likelihood of an event occurring, between 0 and 1.

25. Conditional Probability:
The probability of an event given that another event is already known to have occurred.

26. Bayes' Theorem:
The mathematical rule for updating probability when new evidence arrives.

27. Normal Distribution:
A bell-shaped, symmetric distribution centered around the mean.

28. Skewness:
Measures the asymmetry of a distribution.

29. Correlation:
Measures the strength and direction of the relationship between two variables; correlation is not causation.

30. Covariance:
A measure of how two variables vary together.

31. Hypothesis Testing:
Evaluating a claim based on data and statistical assumptions.

32. P-value:
The probability of observing a result as extreme as, or more extreme than, the one seen, assuming the null hypothesis is true.

33. Confidence Interval:
A parameter-estimation interval with a specified coverage level, in a repeated-sampling framework.

34. Central Limit Theorem:
Under certain conditions, the sampling distribution of the sample mean becomes approximately normal as the sample size grows.

35. Maximum Likelihood Estimation:
Estimating the parameters that give the observed data the highest likelihood.

36. Gradient:
The vector pointing in the direction in which a function increases fastest.

37. Gradient Descent:
Updating parameters in the direction of the negative gradient to reduce the loss.

38. Partial Derivative:
The rate of change with respect to one variable in a multi-variable function.

39. Matrix and Tensor:
A matrix is a 2D numerical structure; a tensor is a multidimensional numerical structure.

40. Eigenvalues and Eigenvectors:
They capture the important directions of linear transformations and help in understanding algorithms such as PCA.

==============================
SECTION 3: DATA CLEANING & FEATURES
==============================

41. Missing Values:
You can use deletion, median/mode imputation, model-based imputation, or missing-value indicators.

42. Duplicate Records:
Identify and remove duplicates based on business keys and data rules.

43. Outliers:
Observations that differ greatly from the overall pattern of the data.

44. Outlier Handling:
Verify whether they are data errors; do not blindly delete valid extreme values. Consider robust models or transformations.

45. Standardization:
Transforming a feature to generally have zero mean and unit standard deviation.

46. Normalization:
Transforming feature values to a specified scale, such as 0 to 1.

47. Label Encoding:
Assigning numerical codes to categories.

48. One-Hot Encoding:
Creating a separate binary indicator for each category.

49. Target Encoding:
Encoding categories using target statistics; use an out-of-fold strategy to avoid leakage.

50. Feature Selection:
Choosing useful features to reduce noise and unnecessary complexity.

51. Feature Extraction:
Creating new useful features or representations from existing inputs.

52. Multicollinearity:
A strong linear relationship between features.

53. VIF:
Variance Inflation Factor is a measure used to assess multicollinearity in regression.

54. Data Leakage:
Using information in training that will not be available at prediction time.

55. Leakage Prevention:
Split first; fit preprocessing and feature selection on the training data only.

56. Data Drift:
The distribution of incoming input data changing over time.

57. Concept Drift:
The relationship between inputs and the target changing over time.

58. Class Imbalance:
When one class has far more examples than another.

59. SMOTE:
Creates synthetic examples of the minority class; apply it on training folds only.

60. Feature Store:
A system to consistently define, manage, serve and reuse features.

==============================
SECTION 4: CORE ML ALGORITHMS
==============================

61. Linear Regression:
Predicts a continuous target through a linear relationship.

62. Logistic Regression:
Used for classification and can estimate probabilities.

63. Decision Tree:
Makes predictions by splitting data using feature-based conditions.

64. Random Forest:
Combines multiple randomized decision trees to improve predictions and control variance.

65. Bagging:
Training models on bootstrap samples and aggregating their predictions.

66. Boosting:
Building models sequentially, where later models try to correct the errors of earlier ones.

67. XGBoost:
A popular library that supports regularization and efficient tree boosting.

68. LightGBM:
An efficient gradient boosting framework that can be useful on large tabular datasets.

69. CatBoost:
A gradient boosting library that can handle categorical features conveniently.

70. SVM:
A Support Vector Machine can solve classification and regression by maximizing the decision boundary or margin.

71. KNN:
An algorithm that predicts based on nearby training examples.

72. K-Means:
Partitions data into K clusters.

73. DBSCAN:
Identifies clusters based on density and can separate out noise points.

74. Hierarchical Clustering:
Creating a hierarchy by progressively merging or splitting clusters.

75. PCA:
Principal Component Analysis transforms high-dimensional data into a lower-dimensional representation.

76. Naive Bayes:
A probabilistic classifier based on Bayes' theorem that uses a conditional independence assumption.

77. Random Forest vs Boosting:
Random Forest trains trees largely independently; boosting adds trees sequentially.

78. Regularization:
Adding a penalty to the objective function to control model complexity.

79. L1 vs L2:
L1 penalizes absolute coefficients and can create sparsity; L2 penalizes squared coefficients.

80. Algorithm Selection:
Choose based on the dataset, latency, interpretability, compute budget and validation performance.

==============================
SECTION 5: MODEL EVALUATION
==============================

81. Confusion Matrix:
Summarizes classification results into TP, TN, FP and FN.

82. Accuracy:
Correct predictions / Total predictions.

83. Precision:
TP / (TP + FP). Of the predicted positive cases, how many were correct.

84. Recall:
TP / (TP + FN). Of the actual positive cases, how many were identified.

85. F1-Score:
The harmonic mean of precision and recall.

86. Specificity:
TN / (TN + FP). Of the actual negative cases, how many were correctly identified.

87. ROC-AUC:
Measures ranking performance across thresholds.

88. PR-AUC:
The area under the Precision-Recall curve assesses positive-class retrieval performance.

89. MAE:
The average of the absolute errors between actual and predicted values.

90. MSE:
The average of the squared prediction errors.

91. RMSE:
The square root of MSE; the error is in the original target units.

92. R-squared:
A measure of explained variation in regression compared with the mean baseline.

93. Cross-Validation:
Assessing stability by training and evaluating the model on multiple folds.

94. Stratified K-Fold:
Approximately preserves class proportions in each fold.

95. Time Series Validation:
Use chronological splits and rolling windows; future data must not leak into training.

96. Hyperparameter Tuning:
Optimizing model settings based on validation performance.

97. Grid Search vs Random Search:
Grid Search tests specified combinations; Random Search samples combinations.

98. Bayesian Optimization:
Choosing promising hyperparameter configurations based on the results of previous trials.

99. A/B Testing:
Evaluating real-world impact by comparing controlled variants.

100. Statistical vs Business Significance:
Statistical significance addresses uncertainty; business significance addresses actual impact and cost.

==============================
SECTION 6: DEEP LEARNING
==============================

101. Neural Network:
A model made of layers of interconnected units that learns complex patterns.

102. Neuron:
Generates an output by taking a weighted combination of inputs and applying an activation function.

103. Activation Function:
Introduces non-linearity into the network; examples are ReLU, sigmoid and tanh.

104. ReLU:
f(x) = max(0, x). It preserves positive values and sets negative values to zero.

105. Sigmoid:
Maps the input to a value between 0 and 1.

106. Softmax:
Converts logits into normalized class probabilities.

107. Forward Propagation:
Calculating the output from the inputs through the layers.

108. Backpropagation:
Calculating loss gradients using the chain rule.

109. Epoch:
One complete pass over the training dataset.

110. Batch Size:
The number of examples processed before one parameter update.

111. Learning Rate:
Controls the step size of the optimizer's parameter updates.

112. Adam Optimizer:
Makes adaptive updates by estimating the first and second moments of the gradients.

113. Vanishing Gradient:
Gradients become very small and the early layers learn slowly.

114. Exploding Gradient:
Gradients become very large and training can become unstable.

115. Dropout:
Applies regularization by randomly disabling some activations during training.

116. Batch Normalization:
Normalizes mini-batch activations and transforms them with learnable parameters.

117. CNN:
A Convolutional Neural Network is useful for images and spatial patterns.

118. RNN:
A Recurrent Neural Network processes sequential inputs through a hidden state.

119. LSTM and GRU:
Gated recurrent architectures that help manage sequence information.

120. Transformer:
An attention-based architecture that models relationships between sequence elements.

==============================
SECTION 7: MLOPS & DEPLOYMENT
==============================

121. MLOps:
Practices that make ML development, deployment, monitoring and lifecycle management reliable.

122. ML Pipeline:
An automated workflow from data ingestion through preprocessing, training, evaluation and deployment.

123. CI/CD:
Continuous Integration and Continuous Delivery/Deployment test and release software changes.

124. Data Versioning:
Tracking datasets and snapshots so that experiments can be reproduced.

125. Model Versioning:
Tracking versions of model artifacts, configurations and metadata.

126. MLflow:
A platform for tracking experiments, metrics, parameters and model artifacts.

127. Model Registry:
Manages model versions, metadata, approval and the deployment lifecycle.

128. Docker:
Packages an application and its dependencies into a container image.

129. Kubernetes:
Deploys, scales and manages containerized applications.

130. FastAPI:
A framework useful for serving a trained ML model through a REST API.

131. Batch Inference:
Running scheduled or grouped predictions on many records.

132. Real-Time Inference:
Generating a prediction when a request arrives.

133. Model Serialization:
Saving a trained model so it can be reloaded in a supported environment.

134. Canary Deployment:
Evaluating a new model by initially giving it limited traffic.

135. Blue-Green Deployment:
Maintaining two environments and switching traffic from the old version to the new one.

136. Shadow Deployment:
Testing a new model on production inputs without using its outputs for user-facing decisions.

137. Rollback:
Restoring the previous stable version when an issue occurs.

138. Training-Serving Skew:
Inconsistency in how features are computed or represented between training and serving.

139. Model Monitoring:
Tracking latency, errors, input drift, prediction quality and operational metrics.

140. Model Retraining:
Retraining based on performance degradation, meaningful drift, new labeled data or scheduled requirements.

==============================
SECTION 8: ML SYSTEM DESIGN
==============================

141. System Design First Step:
Define the business problem, users, prediction target and measurable success criteria.

142. Functional vs Non-Functional Requirements:
Functional requirements state what the system will do; non-functional requirements define latency, security and scalability.

143. Training vs Serving:
The training pipeline builds the model; the serving system loads the model and returns predictions.

144. Data Ingestion:
Bringing validated data into the pipeline from APIs, databases, files or streams.

145. Data Validation:
Checking schema, types, missingness and business constraints.

146. Offline vs Online Features:
Offline features are used for training/batch processing; online features are used for low-latency predictions.

147. Synchronous vs Asynchronous Inference:
Synchronous requests wait for the response; asynchronous processing can happen through a background workflow or queue.

148. Message Queue:
Buffers requests, decouples producers and consumers, and manages traffic spikes.

149. Caching:
Reusing repeated computations or results to reduce latency and compute cost.

150. Horizontal vs Vertical Scaling:
Horizontal scaling adds instances; vertical scaling increases machine resources.

151. Autoscaling:
Automatically adjusting capacity based on traffic, queue depth or resource utilization.

152. Load Balancer:
Distributes incoming traffic across multiple healthy instances.

153. Rate Limiting:
Restricting a client's or user's requests within a defined time window.

154. Circuit Breaker:
Temporarily stops calls to a dependency after repeated failures to reduce cascading failures.

155. Retry and Timeout:
Use bounded timeouts, limited retries and exponential backoff with jitter.

156. Idempotency:
Repeating the same operation should not cause unintended duplicate side effects.

157. High Availability:
Implementing redundancy, health checks, failure isolation and recovery procedures.

158. Disaster Recovery:
Restoring service and data after a failure; define RTO and RPO.

159. SLO, SLA and SLI:
An SLI is the actual service metric, an SLO is the target, and an SLA is a formal service commitment.

160. End-to-End ML Architecture:
Data Sources -> Validation -> Feature Pipeline -> Training -> Evaluation -> Registry -> Deployment -> Monitoring -> Retraining.

==============================
SECTION 9: ADVANCED ML & GENAI
==============================

161. Quantization:
Representing model weights or activations in lower precision to reduce memory and compute requirements.

162. Pruning:
Removing less important weights, neurons or structures to reduce model size or computation.

163. Knowledge Distillation:
Training a smaller student model from the behavior of a large teacher model.

164. Mixed Precision Training:
Optimizing performance and memory by using FP16/BF16 where supported and higher precision where needed.

165. GPU Memory Optimization:
Tune batch size, use mixed precision, free unnecessary tensors and consider activation checkpointing.

166. Distributed Training:
Dividing the training workload across multiple devices or machines.

167. Data Parallelism:
Model replicas process different data batches and synchronize gradients.

168. Model Parallelism:
Different parts of the model are placed on multiple devices.

169. Hyperparameter Optimization Cost:
Estimate as Trials x Average Runtime x Compute Cost per Time Unit; also consider overhead and failed runs.

170. GPU Hours:
GPU Hours = Number of GPUs x Runtime in Hours.

171. TFLOPS:
A measure of compute throughput in trillions of floating-point operations per second.

172. LoRA:
Low-Rank Adaptation can reduce fine-tuning cost by adding trainable low-rank matrices alongside a pretrained model.

173. Fine-Tuning vs RAG:
Fine-tuning adapts model behavior; RAG retrieves external knowledge at inference time.

174. Embeddings:
Numerical vector representations of text, images or other inputs.

175. Vector Database:
A database optimized for storing embeddings and running similarity search.

176. Semantic Search:
Finding relevant results through meaning-related representations.

177. RAG Pipeline:
Documents -> Chunking -> Embeddings -> Retrieval -> Context Assembly -> LLM -> Response.

178. Hallucination:
When a model generates unsupported, incorrect or fabricated information.

179. LLM Evaluation:
Evaluating task quality, factuality, relevance, groundedness, latency, token cost and safety.

180. AI Guardrails:
Limiting unsafe behavior through input validation, access control, output checks and policy enforcement.

==============================
SECTION 10: SENIOR ENGINEERING & SECURITY
==============================

181. Business Impact:
Tracking metrics such as revenue, avoided loss, conversion, customer experience and operational cost.

182. Cost-Performance Tradeoff:
Balancing accuracy, latency, reliability and operating cost according to business priorities.

183. Model Latency Optimization:
Use profiling, batching, caching, quantization and efficient serving.

184. Throughput:
How many requests or records the system processes per unit of time.

185. P95/P99 Latency:
P95 and P99 are the latency thresholds under which 95% and 99% of measured requests complete, respectively.

186. Explainability:
Helping stakeholders understand predictions and the important factors influencing them.

187. SHAP:
A framework that explains feature contributions through Shapley values.

188. Model Fairness:
Compare metrics across relevant groups and evaluate context-appropriate fairness criteria.

189. Threat Modeling:
Designing security controls by identifying assets, trust boundaries, attackers and possible attack paths.

190. Adversarial Attack:
Deliberately modifying inputs to try to manipulate a model's prediction.

191. Data Privacy:
Applying data minimization, encryption, access control, retention policies and suitable de-identification.

192. Secrets Management:
Handling API keys, credentials and tokens with secure secret stores or appropriate secret management.

193. Model Artifact Security:
Verify artifact provenance, restrict access and avoid loading untrusted serialized models.

194. ML Incident Response:
Detect the issue, assess impact, apply a safe fallback or rollback, and document the incident.

195. Root Cause Analysis:
Identifying the underlying reason for a failure to prevent recurrence.

196. Technical Debt:
Shortcuts and design compromises that can increase future maintenance, reliability or delivery cost.

197. Architecture Decision Record:
Documenting an important technical decision, the alternatives and the rationale.

198. Code Review:
Checking correctness, tests, readability, security, edge cases, performance and maintainability.

199. Senior ML Engineer Responsibilities:
Designing reliable ML systems, justifying tradeoffs, taking production ownership and technically guiding the team.

200. Senior ML Engineer Mindset:
Business Problem -> Data Validation -> Baseline -> Model Evaluation -> Production Deployment -> Monitoring -> Cost and Quality Improvement.
