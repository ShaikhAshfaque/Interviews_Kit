SECTION 1: MLOPS FUNDAMENTALS
============================================================

1. QUESTION:
MLOps kya hai?

ANSWER:
MLOps ka full form Machine Learning Operations hai.

MLOps ka purpose ML/AI models ko development se production tak
reliably build, deploy, monitor aur maintain karna hai.

Simple flow:

Data
 ↓
Training
 ↓
Evaluation
 ↓
Model Registry
 ↓
Deployment
 ↓
Monitoring
 ↓
Retraining


2. QUESTION:
MLOps aur DevOps mein difference kya hai?

ANSWER:

DevOps mainly software applications ke lifecycle par focus karta hai.

MLOps mein software ke saath additional ML concerns bhi hote hain:

- Data
- Features
- Models
- Experiments
- Model drift
- Data drift
- Model performance
- Retraining

MLOps = DevOps + ML lifecycle management.


3. QUESTION:
MLOps ki need kyun hai?

ANSWER:
Notebook mein model banana easy hai.

Production mein problems aati hain:

- Data change
- Model degradation
- Dependency conflicts
- Scaling
- Deployment failures
- Monitoring
- Security
- Reproducibility

MLOps in problems ko systematically manage karta hai.

SECTION 2: VERSION CONTROL
============================================================

11. QUESTION:
Git MLOps mein kyun important hai?

ANSWER:
Git code aur configuration versioning ke liye use hota hai.

Track kar sakte hain:

- Code changes
- Config changes
- Prompt changes
- Pipeline changes


12. QUESTION:
Kya Git mein large ML models store karne chahiye?

ANSWER:
Generally nahi.

Large models ke liye:

- Model registry
- Object storage
- Artifact storage
- Git LFS

use kiya ja sakta hai.


13. QUESTION:
Git LFS kya hai?

ANSWER:
Git Large File Storage large files ko Git repository se separately
store/manage karne ke liye use hota hai.

ML models aur large datasets ke liye useful hai.


14. QUESTION:
Branching strategy kya hai?

ANSWER:
Different development streams ko manage karne ka strategy.

Example:

main
develop
feature/*
release/*

Senior engineer ko team ke deployment workflow ke according strategy choose karni chahiye.


15. QUESTION:
Code review MLOps mein kyun important hai?

ANSWER:
Code quality, security, bugs aur production risk reduce karne ke liye.

AI systems mein review hona chahiye:

- Model code
- Prompt code
- Data pipelines
- Infrastructure
- Security configuration


16. QUESTION:
Git commit mein kya avoid karna chahiye?

ANSWER:
Secrets kabhi commit nahi karne chahiye.

Avoid:

- API keys
- Passwords
- Tokens
- Private keys
- Database credentials


17. QUESTION:
Secrets accidentally Git mein push ho jaye to?

ANSWER:

1. Secret immediately rotate karo.
2. Old credential revoke karo.
3. Git history clean karo if required.
4. Secret manager use karo.
5. Secret scanning enable karo.


18. QUESTION:
Configuration aur code separate kyun rakhte hain?

ANSWER:
Same code ko different environments mein use kar sakte hain.

Example:

Development:
DB_DEV

Staging:
DB_STAGE

Production:
DB_PROD


19. QUESTION:
Infrastructure as Code kya hai?

ANSWER:
Infrastructure ko manually create karne ke instead code ke through define
aur manage karna Infrastructure as Code hai.

Tools:

- Terraform
- Pulumi
- CloudFormation


20. QUESTION:
MLOps mein GitOps kya hai?

ANSWER:
Infrastructure aur deployment configuration ko Git as source of truth
ke through manage karna GitOps approach hai.

SECTION 3: DATA VERSIONING
============================================================

21. QUESTION:
Data versioning kya hai?

ANSWER:
Different versions of datasets ko track karna data versioning hai.

Important because model performance data par depend karti hai.


22. QUESTION:
Data versioning kyun important hai?

ANSWER:
Agar model performance change ho gayi to identify karna hota hai:

- Code changed?
- Data changed?
- Feature changed?
- Model changed?

Data versioning is problem ko solve karta hai.


23. QUESTION:
DVC kya hai?

ANSWER:
DVC ka full form Data Version Control hai.

DVC data aur ML artifacts ko version karne ke liye use ho sakta hai.


24. QUESTION:
Dataset lineage kya hai?

ANSWER:
Dataset kaha se aaya, kaise transform hua aur kis model mein use hua,
iska complete history dataset lineage hai.


25. QUESTION:
Data validation kya hai?

ANSWER:
Training/inference se pehle data quality check karna.

Checks:

- Schema
- Missing values
- Data types
- Range
- Duplicates
- Distribution


26. QUESTION:
Schema validation kya hai?

ANSWER:
Ensure karna ki incoming data expected structure follow kar raha hai.

Example:

Expected:

id: int
name: string
age: int

Agar age string aa gaya to pipeline reject kar sakti hai.


27. QUESTION:
Data quality dimensions kya hain?

ANSWER:

- Accuracy
- Completeness
- Consistency
- Validity
- Uniqueness
- Timeliness


28. QUESTION:
Data drift kya hai?

ANSWER:
Production data ki distribution training data se change ho jaye,
to data drift kehte hain.


29. QUESTION:
Concept drift kya hai?

ANSWER:
Input aur target ke relationship mein change aa jaye to concept drift hai.

Example:

Customer behavior change hone ke baad old fraud pattern kaam nahi karta.


30. QUESTION:
Data drift vs concept drift?

ANSWER:

Data Drift:
Input distribution change.

Concept Drift:
Input-output relationship change.

SECTION 4: FEATURE ENGINEERING
============================================================

31. QUESTION:
Feature engineering kya hai?

ANSWER:
Raw data ko useful model features mein transform karna feature engineering hai.


32. QUESTION:
Feature store kya hai?

ANSWER:
Features ko centrally store, manage aur serve karne ka system feature store hai.

Benefits:

- Reuse
- Consistency
- Feature lineage
- Online/offline serving


33. QUESTION:
Offline feature store kya hai?

ANSWER:
Historical training aur batch processing ke liye features store karta hai.


34. QUESTION:
Online feature store kya hai?

ANSWER:
Low-latency real-time inference ke liye latest features provide karta hai.


35. QUESTION:
Training-serving skew kya hai?

ANSWER:
Training aur production inference mein feature generation different hone
par training-serving skew hota hai.

Ye model performance degrade kar sakta hai.


36. QUESTION:
Feature leakage kya hai?

ANSWER:
Aisi information feature mein aa jaye jo prediction time par available nahi thi,
to data leakage/feature leakage hota hai.


37. QUESTION:
Data leakage dangerous kyun hai?

ANSWER:
Model offline evaluation mein artificially high performance dikha sakta hai
but production mein fail ho sakta hai.


38. QUESTION:
Feature pipeline production mein kaise manage karenge?

ANSWER:

Raw Data
 ↓
Validation
 ↓
Transformation
 ↓
Feature Store
 ↓
Training / Inference


39. QUESTION:
Feature freshness kya hai?

ANSWER:
Feature ka latest available data ke saath kitna updated hona feature freshness hai.

Real-time fraud systems mein freshness critical ho sakti hai.


40. QUESTION:
Feature monitoring kya hai?

ANSWER:
Production features ki:

- Distribution
- Missingness
- Range
- Freshness
- Cardinality

monitor karna.

55. QUESTION:
Model rollback kya hai?

ANSWER:
Production mein problem hone par previous stable model version par return karna.


56. QUESTION:
Rollback kab karenge?

ANSWER:

- Accuracy drop
- Latency increase
- Error rate increase
- Data incompatibility
- Security issue
- Cost increase


57. QUESTION:
Canary deployment kya hai?

ANSWER:
New model ko initially small percentage traffic dena.

Example:

95% → Old Model
5%  → New Model

Agar new model stable hai to traffic gradually increase karenge.


58. QUESTION:
Blue-Green deployment kya hai?

ANSWER:
Do production environments maintain karte hain.

Blue:
Current production.

Green:
New version.

Validation ke baad traffic Green par switch kar dete hain.


59. QUESTION:
Shadow deployment kya hai?

ANSWER:
New model ko production inputs milte hain but user ko uska response serve nahi hota.

Old model actual response deta hai.

New model evaluation ke liye run hota hai.


60. QUESTION:
A/B testing aur Canary mein difference?

ANSWER:

Canary:
Gradual traffic rollout.

A/B:
Different users/groups ko different versions dekar compare karna.

Kubernetes containerized applications ko deploy, scale aur manage karne ka

82. QUESTION:
Kubernetes AI systems mein kyun useful hai?

ANSWER:

- Scaling
- Self-healing

83. QUESTION:

2 pods

10 pods

89. QUESTION:
GPU scheduling Kubernetes mein kyun important hai?

90. QUESTION:

Old pods ko gradually new pods se replace karna without complete downtime.

SECTION 15: MONITORING
============================================================

141. QUESTION:
ML monitoring kya hai?

ANSWER:
Production ML system ke health aur performance ko continuously observe karna.


142. QUESTION:
Traditional application monitoring vs ML monitoring?

ANSWER:

Traditional:
- CPU
- Memory
- Errors
- Latency

ML:
Above +
- Data drift
- Model drift
- Prediction distribution
- Accuracy
- Feature drift


143. QUESTION:
Model drift kya hai?

ANSWER:
Model ki production performance time ke saath degrade ho jaye.

Causes:

- Data changes
- User behavior changes
- Environment changes


144. QUESTION:
Data drift monitor kaise karenge?

ANSWER:
Training aur production data distributions compare karenge.

Methods:

- PSI
- KS test
- Distribution comparison
- Statistical tests


145. QUESTION:
PSI kya hai?

ANSWER:
PSI = Population Stability Index.

Population distribution mein change measure karne ke liye use hota hai.


146. QUESTION:
KS Test kya hai?

ANSWER:
Kolmogorov-Smirnov test distributions ke difference ko compare karne ke liye
use ho sakta hai.


147. QUESTION:
Model performance monitoring kaise karenge?

ANSWER:

If labels available:

- Accuracy
- Precision
- Recall
- F1
- AUC
- RMSE

Agar labels delayed hain:

- Proxy metrics
- Data drift
- Prediction distribution
- Business KPIs


148. QUESTION:
Prediction drift kya hai?

ANSWER:
Model predictions ki distribution time ke saath change ho jaye.


149. QUESTION:
Latency monitoring mein p95/p99 kyun important hai?

ANSWER:
Average latency tail behavior hide kar sakti hai.

p95/p99 slow requests ko identify karne mein useful hain.


150. QUESTION:
SLI kya hai?

ANSWER:
SLI = Service Level Indicator.

Actual measured service metric.

Example:

API latency.

SECTION 16: SLO, SLA AND INCIDENTS
============================================================

151. QUESTION:
SLO kya hai?

ANSWER:

Service ke desired performance target.

99.9% successful requests.


152. QUESTION:
SLA kya hai?

ANSWER:

Customer/provider ke beech formal service commitment.


153. QUESTION:

ANSWER:

Actual measurement.

SLO:
Internal target.

SLA:
Formal commitment.

Distributed AI systems mein cascading failures prevent karne ke liye useful.
